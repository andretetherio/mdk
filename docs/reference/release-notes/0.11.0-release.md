# Release v0.11.0

## Overview

v0.11.0 is a caller-identity release. Kernel's allowlist admits a backend process by the DHT key it dials with. In 0.11 every plugin
dials with the Gateway's persistent key, the one the Gateway publishes as `status.rpcClientKey`, and one allowlist entry admits the
whole Gateway across restarts.

The identity seeds behind those keys also move. Local state now lives under `~/.mdk`, created owner-only, instead of the shared OS temp
directory.

The release also makes a lost Kernel connection report one error code on every request, and gives the agent package a relaxed
tool-admission mode for domain agents running stronger models.

## Breaking changes

**The default data root is `~/.mdk`.** `getKernel()` and `startGateway()` default to `~/.mdk` and `~/.mdk/gateway`, and
`DEFAULT_TOPIC_FILE` / `DEFAULT_KEY_FILE` move with them. State under the old `os.tmpdir()/mdk` location is not read after upgrading,
so a stack on the defaults starts with a new Kernel store, DHT topic and Gateway identity. Allowlist the new `status.rpcClientKey`, or
pass `opts.root` to keep the previous directory. The full table is in [`CHANGELOG.md`](../../../CHANGELOG.md).

## What's new

**A caller keypair for `@tetherto/mdk-client`**: `createMdkClient()` accepts `config.kernelKeyPair` and dials Kernel with it, so the
allowlist can name the caller. Inside a Gateway plugin it is already set to the Gateway's key.

**Relaxed tool admission in `@tetherto/mdk-agent`**: `strictToolGating: false` admits standard MCP tools that don't follow the
small-model naming and metadata contract, for an agent on a `mid` or `large` model. Tools without a declared mutability, or named with
a mutating verb, stay behind the approval gate. The vocabulary also gains `report` and `measurement` entities.

**Charter provenance**: `createAgent()` takes `charter` (an alias for `system`) and `charterVersion`, sessions carry both, and eval
manifests record the charter version, a hash of the exact system prompt, and the gating mode.

## Security

**Identity seeds are owner-only**: Data directories are created with mode `0700` and new Worker seed files with mode `0600`. Together
with the move out of the shared temp directory, another local user can no longer copy a seed and present the Gateway's or a Worker's
identity.

## Fixed

**Allowlisting the Gateway admits its plugins**: A non-empty `auth.whitelist` with the Gateway's `status.rpcClientKey` on it used to
refuse every plugin's Kernel client. It now admits them.

**A lost Kernel connection reports `ERR_MDK_CLIENT_UNAVAILABLE`**: Requests through `createMdkClient` that fail to reach Kernel now
reject with that code, with the original error as `cause`, instead of a raw transport error.
